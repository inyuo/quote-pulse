## 四、碰撞空态分类与默认地址（同日下午，用户反馈后确认）

**现象**：量化面板数据碰撞显示「数据服务暂不可用 / 请配置 leek-fund.dataApiBaseUrl / dataApiKey 后重试」。

**排查结论**：不是服务端故障。本机 17 个 IDE `settings.json` 全部没有 `leek-fund.dataApi*` 配置 → `getCollision()` 在发请求前 `if (!baseUrl) return null` → 宿主下发 `unavailable:true`。服务端 8800 可达，`/api/v1/health` 与 `/api/v1/quant/collision` 均返回 `401 invalid api key`，说明服务在线且鉴权生效。SSH 到 `root@124.71.128.214` 卡在 `Host key verification failed`，未代取密钥、未代写 IDE 配置。

**用户确认后实施的改进**（不再一律提示「请配置」）：
- `getCollision()` 返回 `CollisionResult {ok, reason, status, data}`，原因分为 `unconfigured` / `unauthorized`(401/403) / `unreachable`(5xx、无响应体、网络异常) / `no_data`(服务端 `{success:false,data:null,error:'no_data'}`) / `invalid_response`。服务端 `_json_response` 在 `payload=None` 时固定带 `error:'no_data'`，因此分类只认该标记（外加无 error 且 data 为 null 的兜底）。
- `quantPanel.ts` 透传 `reason` / `httpStatus`；**只缓存成功快照**（原实现把所有失败也缓存 60s，配置修好后点重试仍可能拿旧错误），失败结果每次都重新请求。
- `quant.html` 按 5 类原因显示不同标题与引导（未配置→填两项、401→核对 `QP_API_KEY`、无快照→等待服务端下一轮抓取、连接失败→检查 8800、响应异常→检查服务端版本），均带「重试」按钮。
- `leek-fund.dataApiBaseUrl` 默认值改为 `http://124.71.128.214:8800`（只省地址，密钥仍为空、**不入库**），用户现在只需填 `leek-fund.dataApiKey`。注意这会让 `isEnabled()` 对所有用户为 true，未填 key 时请求返回 401 并显示「API Key 无效」。
